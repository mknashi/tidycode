When Your JSON Won't Format

JSON has to be valid before it can be formatted. When it isn't, the error panel shows the parser's message with the line and column, and clicking the error moves the cursor there. This file is missing a comma at the end of line 3:

{
  "name": "tidycode",
  "version": "1.0.1"
  "private": true
}

In Chrome, the error reads:

Expected ',' or '}' after property value in JSON at position 47 (line 4 column 3)

The parser reports where it noticed the problem, at the start of line 4, so the mistake is usually just before the position it gives.

The usual causes

  • A trailing comma after the last item in an object or array
  • Property names without double quotes
  • Single quotes instead of double quotes
  • A missing comma between two properties
  • An unclosed { or [
  • Comments (// or /* */), which JSON doesn't allow

Fix JSON: Local Rules First, Optional AI

Choose Fix JSON in the error panel. Auto Fix is always selected and tries local rules first. The Use AI if rule-based fixing fails checkbox is checked by default; uncheck it to use local rules only.

With Private AI selected, supported desktop Chrome installations can try experimental Gemini Nano repair for JSON up to 8,192 characters. Prepare the model first. Repairs may be refused if they cannot be validated safely. Private AI does not automatically fall back to cloud AI: a named cloud retry sends the original document only when you click it.

Review the suggested changes in the diff before accepting. Replace current tab is selected by default when the source is still active and unchanged, and the replacement supports Undo. Choose Open in new tab to keep the original. Accept All Changes also formats the accepted JSON; accepting selected changes does not automatically format it.

What Formatting Changes, and What It Doesn't

Automatic formatting on paste and after Accept All Changes preserves numeric spelling, duplicate keys, and string escapes. The manual Format button and automatic formatting on file open instead parse and rewrite JSON, with these consequences:

  • 1.50 becomes 1.5 and 1e3 becomes 1000: the same values in shorter notation
  • Escapes such as \u00e9 are written as the character itself (é)
  • If a key appears twice in the same object, only the last value is kept
  • Integers larger than 9,007,199,254,740,991 lose precision: 12345678901234567890 becomes 12345678901234567000

If your JSON carries very large numeric IDs, keep the original file and use the formatted copy for reading only.

Walkthrough: Review a Missing-Comma Repair

Paste {"name":"Garden" "available":true}. A comma is missing between the two properties. The error panel identifies the invalid JSON; click Fix JSON to try local rules first.

The expected result is {"name":"Garden", "available":true}. Check that the name is still Garden and available is still the boolean true. Keep Replace current tab to apply with Undo available, or choose Open in new tab. Accept All Changes applies the repair and formats the JSON.

When a Proposed Nano Repair Is Refused

Consider {"count":12 "active":true}. Inserting the missing comma preserves the data. A proposed output of {"count":"12","active":true} also parses, but turns a number into a string. Nano's repair guard rejects that proposal rather than presenting it as a safe fix. The original stays unchanged.

This illustrates a checked rejection rule, not a promise that the model always produces that output or that local rules fail on this input. Nano is optional, runs only after local rules fail, and may also reject harmless changes. If repair fails, correct the source manually or explicitly choose a configured cloud retry; always review its proposed changes.

Frequently Asked Questions

How do I beautify JSON online?

Open Tidy Code with the Format JSON now button and paste valid JSON to format it automatically with 2-space indentation. Use the Format button to format manually. JSON files under 100 KB are also formatted automatically when opened; see the formatting caveats on this page.

Why does it say my JSON is invalid?

The most common causes are a trailing comma after the last item, property names or strings in single quotes or no quotes, a missing comma between properties, an unclosed bracket, or comments, which JSON doesn't allow. The error panel shows the line and column where the parser stopped; the mistake is usually just before that point.

Does formatting change my data?

Paste formatting and formatting after Accept All Changes preserve JSON tokens, including numeric spelling, duplicate keys, and escapes. Manual Format and automatic formatting on file open parse and rewrite JSON: numbers and escapes are normalized, duplicate keys keep only the last value, and large integers can lose precision. Keep the original when those details matter.

Is my JSON sent to a server?

No. Formatting and validation run entirely in your browser. The only exception is if you choose to use an AI feature with a cloud AI provider, which receives the text you send it.
